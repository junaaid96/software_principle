# 19 · SDLC and Agile

## SDLC phases
Requirements → Design → Implementation → Testing → Deployment → Maintenance. Models differ in how they move through these phases:
| Model | Idea | Fit |
|---|---|---|
| Waterfall | sequential phases, sign-off between them | fixed, well-understood scope; regulated domains |
| V-model | each phase has a matching test phase | safety-critical systems |
| Iterative / Spiral | repeated cycles with risk analysis | large, risky projects |
| Agile | short iterations delivering working software, continuous feedback | most product work |

## Agile Manifesto values
Individuals and interactions over processes and tools · Working software over comprehensive documentation · Customer collaboration over contract negotiation · Responding to change over following a plan.

## Scrum
- **Roles:** Product Owner (what/why), Scrum Master (process, removes blockers), Developers (how).
- **Events:** Sprint (1–4 weeks), Sprint Planning, Daily Scrum, Sprint Review, Retrospective.
- **Artifacts:** Product Backlog, Sprint Backlog, Increment; Definition of Done.

## Kanban
Visualise work on a board, **limit work in progress (WIP)**, manage flow, measure lead/cycle time. No fixed sprints; good for support and ops work.

## Extreme Programming (XP)
Engineering practices: TDD, pair/mob programming, continuous integration, small releases, simple design, refactoring, collective code ownership.

## Practical tools
- User stories: *As a member, I want to renew a loan so that I can keep the book longer.*
- Acceptance criteria in Given/When/Then.
- INVEST stories: Independent, Negotiable, Valuable, Estimable, Small, Testable.
- Estimation: story points, t-shirt sizes; forecast with throughput rather than promises.
